# Public canary: staged, owner credential required

The dedicated synthetic FrankenPHP origin and isolated TLS path are running and locally validated. A separate remotely configured Cloudflare tunnel was created; its configuration is exact-host unix+tls with explicit CA and SNI verification and default 404. No DNS record has been created. The initial systemd 249 incompatibility was rolled back and corrected. Automated credential delivery was blocked by the tool security control; no token file was created, no connector started, and the ephemeral transfer key was removed. No workaround was attempted. The owner can enter the dedicated token directly in a trusted terminal using the interactive helper; the helper verifies tunnel/account binding and writes the credential root-only without echo, argv or GitHub storage. Connector health, external HTTPS and DNS still require verification. The local origin certificate expires after 30 days; renewal and reboot lifecycle are not enabled. The canary consumes the single available private deployment slot until removed. Feast and existing sites, wildcard DNS and MCP connector were not changed.
