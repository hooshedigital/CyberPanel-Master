# مرحله چهارم — مولد مستقل پیکربندی

ماژول web_engine_config.py فقط متن پیکربندی و manifest با SHA256 برمی‌گرداند. هیچ فایل، سرویس، حساب، پورت یا سایت ایجاد نمی‌کند. محدوده خروجی فقط fixture مصنوعی در /var/tmp/hoosh-engine-render-* و دامنه .test است. فقط نقش مدیر، یک یا دو سایت، UIDهای آزمایشی و پروفایل Eco/Balanced پذیرفته می‌شوند. دامنه، UID و slot تکراری رد می‌شوند. فهرست UID و دامنه‌های اشغال‌شده باید از آداپتور معتبر تأمین شود.

در این مرحله Apache پیش‌فرض دامنه ناشناخته را رد می‌کند و .htaccess غیرفعال است؛ بر خلاف آزمون قبلی که rewrite آزمایشی را اجازه می‌داد، اجازه دادن به فایل htaccess قابل ویرایش مشتری بدون تحلیل proxy/rewrite/handler خطرناک است. سیاست نهایی باید قوانین سازگار را به شکل محدود و آزموده فراهم کند. کش، HTTPS و فعال‌سازی واقعی فرم در این مرحله انجام نمی‌شوند.

اجرای FPM با UID غیر root و بدون گروه اضافی اجباری است؛ فایل FPM برای اجرای root طراحی نشده. مالکیت مسیرها، عدم symlink، استفاده نشدن UID/GID و پورت، شبکه و PID خصوصی، اعتبارسنجی runtime و تأیید مالک باید در آداپتور بعدی بررسی شوند. Manifest صرفاً برای بازبینی و تشخیص تغییر محتوا است؛ امضا یا مجوز اجرا نیست.

آزمون: python3 -m unittest master_extensions.tests.test_web_engine_config -v

مرحله بعد: اجرای پیکربندی تولیدشده در محیط ایزوله، آزمون Host/SNI و header و cache privacy، سپس طراحی تراکنش ایجاد سایت و rollback، RBAC/CSRF و اتصال واقعی فرم. هیچ قابلیت تجاری یا شرط Premium تغییر نکرده است.
