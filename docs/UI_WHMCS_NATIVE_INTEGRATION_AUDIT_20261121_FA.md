## ۳. قرارداد واقعی پنجره WHMCS

پنجره در صفحه CyberPanel Master شامل بخش‌های \`billing\`, \`catalog\`, \`packages\`, \`provisioning\`, \`affiliates\`, \`identity\` است. انتخاب تب در **خود صفحه** و به‌صورت server-side انجام می‌شود؛ پارامتر \`commerce\` فقط یکی از مقادیر مجاز را می‌پذیرد. کد UI از سورس ثبت‌شده \`commerce_modules.py\` استفاده می‌کند تا دسته‌بندی تکراری ساخته نشود.

دکمه «ورود به مدیریت WHMCS» تنها در صورت پیکربندی URL معتبر نمایش داده می‌شود و پنل WHMCS را با ورود و 2FA مستقل در تب امن باز می‌کند. **این به معنی API متصل، SSO، گزارش مالی واقعی یا انجام عملیات حسابداری در CyberPanel نیست.**

\`iframe\` شخص ثالث **عمداً ساخته نشد**؛ چون WHMCS ممکن است به‌درستی از طریق \`X-Frame-Options\` / \`Content-Security-Policy frame-ancestors\` از جاسازی بین دامنه‌ها جلوگیری کند. بازکردن این محدودیت یا reverse-proxy ورود مدیر، بدون ممیزی CSRF/Cookie/CSP/2FA ریسک امنیتی جدی دارد. راه درست برای عملیات واقعی داخل پنل، **API محدود و read-only/role-scoped** است، با استفاده از پروژه قبلی \`cp-whmcs\` و ماژول \`hooshcloud\`، فقط پس از ممیزی نسخه نصب‌شده. در این PR credential یا API ساختگی اضافه نشده است.

## ۴. نصب/استقرار: هنوز انجام نشده

سورس زنده در \`/usr/local/CyberCP\` و نسخهٔ Core هنوز باید با staging تطبیق داده شود. قالب پوسته در build جدید تنها وقتی patch می‌شود که یک social header native مشخص و یکتا پیدا شود؛ اگر پیدا نشود، عملیات **fail closed** می‌کند و نیازمند source audit است. تغییر خودکار fallback به sidebar یا overlay شناور ممنوع است.

**گیت‌های انتشار:**
1. بررسی دقیق markup و CSS هدر زنده + محل social icons؛ آزمون رندر در ۳۹۰/۷۶۸/۱۴۴۰ پیکسل در fa/RTL و en/LTR، روشن/تیره.
2. بررسی ورود واقعی Turnstile، 2FA، CSRF، نقش admin و عدم افشای لینک WHMCS برای کاربر غیرمجاز.
3. ممیزی نسخه و مسیر واقعی WHMCS و adapter قدیمی \`cp-whmcs\`؛ تنظیم مخفی و root-owned آدرس و اعتبار API (بدون ورود به repo عمومی).
4. استفاده از backup byte-identical + UID/GID/mode و rollback قبل از هر deploy؛ گزارش source↔production hash.
5. بازبینی امنیتی CSP، cookie domain، CORS و مرز مالکیت خدمات. هزینه/عملیات مالی در WHMCS می‌ماند.
6. کاتالوگ ترجمه Core هنوز کامل نیست (طبق ممیزی قبلی #34 فقط حدود ۵٫۳٪ از رشته‌های gettext بررسی‌شده ترجمه داشتند) و نباید «تمام پنل دو‌زبانه» اعلام شود.
7. نسخه‌های پیشین PRها به ترتیب بررسی و merge شوند: #2 → #3 → #12 → #17 → #27 → #34 → #38؛ #22 به‌عنوان مسیر مستقل عملیات دیسک از #17 منشعب شده و قبل از ادغام باید تعارض‌های آن حل شوند.
