# Compose log retention policy — Stage
Explicit json-file max-size 10m/max-file 3 for chosen services. The tool stages a copy, refuses aliases/anchors, duplicate keys, existing conflicting policies, missing services and Feast. YAML data comparison ensures only selected logging keys change. Never emits source/config values, never calls Docker, never edits its input or recreates containers.
Live inventory: daemon default already json-file 10m/3; 16 running containers without explicit bounded logging. Source checkout provenance for internal Talent Stage and CyberPanel Stage could not be independently mapped to accessible GitHub repositories. Therefore only a locally verified overlay/patch may be deployed with exact source fingerprints, owner-only rollback backup and YAML equivalence checks. No production changes; no automatic recreation. Existing logs and containers remain untouched, and no disk space is immediately reclaimed by configuration alone. Apply at next authorized controlled deployment when capacity permits; sync corresponding source repo after provenance is verified. The 10m/3 limit caps rotated json-file logs approximately 30 MiB/container, not all app logs or exact filesystem consumption.
