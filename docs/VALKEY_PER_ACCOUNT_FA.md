# کش مستقل Valkey به ازای حساب پروژه

این زیرساخت از Redis اصلی جداست. برای داده موقت و قابل حذف (object cache) طراحی شده و برای نشست‌ها، صف پایدار، دیتابیس اصلی یا داده غیرقابل بازیابی مناسب نیست. هر instance سوکت خصوصی در /run/hoosh-valkey-ACCOUNT/cache.sock دارد، TCP خاموش، persistence خاموش، سقف داده 32MiB، MemoryMax=96MiB، CPUQuota=20%. سقف اشتراکی کل نمونه‌ها 192MiB/30% CPU است. شروع هم‌زمان تعداد زیاد instance می‌تواند باعث برخورد با سقف حافظه شود؛ هر workload جداگانه ارزیابی شود.

حساب باید غیرمشترک، اختصاصی پروژه، UID >=1000 و <65000، GID >=1000 داشته باشد و نامش از مجموعه حساب‌های مشترک/مدیریتی مستثنی باشد. مالک سرور بعد از بررسی اختصاصی بودن UID/GID و تطبیق PHP/app worker با همان UID، فایل enrollment ریشه را با محتوای دقیق ACCOUNT:UID:GID و newline نهایی در /etc/hoosh-runtimes/valkey-accounts/ACCOUNT ایجاد می‌کند. مسیر و فایل باید root-owned و غیرقابل نوشتن توسط دیگران باشند؛ فایل 0644. سپس systemctl start hoosh-valkey@ACCOUNT.service. هیچ web-to-root یا تغییر خودکار مشتری وجود ندارد. ابتدا plugin/app را فقط برای داده قابل حذف با سوکت خصوصی تنظیم و صحت آن را بررسی کنید. توقف سرویس کش داده را از دست می‌دهد؛ برای rollback تنظیم اتصال برنامه را به قبلی برگردانید و نمونه را stop کنید. این template عمداً Install section ندارد، و فعال‌سازی پایدار به سیاست lifecycle مصوب نیاز دارد.

این فایل‌ها به معنای مهاجرت خودکار Redis یا فعال‌سازی کش مشتری نیستند. UID/GID و مالکیت پروژه باید از inventory معتبر سرور تأیید شود. مسیر نصب /etc/systemd/system/hoosh-valkey@.service و hoosh-valkey.slice و /usr/local/libexec/hoosh-valkey-account-check است. هیچ رمز یا داده مشتری در GitHub نگهداری نشود.
