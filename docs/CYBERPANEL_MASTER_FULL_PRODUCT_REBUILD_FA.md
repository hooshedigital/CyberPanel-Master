# CyberPanel Master — بازطراحی کل محصول

**زمان:** ۲۰ نوامبر ۲۰۲۶  
**نسخه کد در شاخه توسعه:** `0.2.0-dev.1`  
**نسخه نصب‌شده فعلی:** `0.1.0` با عملیات خواندنی مرحله قبل؛ این تغییرات جدید **هنوز در سرور اصلی نصب نشده‌اند**.

## تعریف و نام‌گذاری صحیح

CyberPanel Master نام **کل محصول مدیریت میزبانی** است. پنل مبتنی بر CyberPanel Core به‌علاوه توسعه‌های مستقل، یک محصول واحد است. صفحه `/backup/master/` فقط **Operations Center** یا «مرکز عملیات» است؛ هیچ محصول جداگانه‌ای با نام Master داخل محصول اصلی وجود ندارد. نسخه Core و Master مستقل اعلام می‌شوند.

## دامنه دو‌زبانه‌سازی

- پیش‌فرض همه صفحات انگلیسی (`en`) است، مستقل از زبان مرورگر؛ فارسی (`fa`) زبان دوم انتخابی است.
- یک انتخاب‌گر **سراسری در نوار اصلی** برای کل محصول، به جای دکمه‌ای که فقط یک ماژول را ترجمه کند.
- از `LocaleMiddleware` و `django.po / django.mo` استفاده شود؛ ترجمه پوسته Django به معنای ترجمه متن‌ها و اعتبارسنجی JavaScript/AngularJS نیست.
- `scripts/plan_global_locale.py` تغییرات لازم را روی **کپی** از نسخه واقعی `CyberCP/settings.py`، `CyberCP/urls.py` و `baseTemplate/index.html` می‌سازد. اگر ساختار واقعی فرق کند، fail-closed؛ بدون بازنویسی مستقیم Core.
- قالب‌های موجود با انتخاب زبان، `lang` و `dir` مناسب، `gettext`، `djangojs` و پشتیبانی RTL متناظر شوند؛ زبان HTML تنها یک مرحله از کار است.
- از سورس upstream `usmannasir/cyberpanel:stable` در ۲۰ نوامبر، ۱۴۲ رشته مستقل منو/command palette شناسایی و در `locale/fa/LC_MESSAGES/django.po` ترجمه اولیه شده‌اند. **این ۱۴۲ عبارت برابر کل برنامه نیست**.
- `scripts/compile_controlled_locale.py` کاتالوگ را در محیط staging به `.mo` تبدیل می‌کند؛ بدون دانلود وابستگی یا دسترسی به هسته زنده.
- `scripts/audit_core_localization.py` برای فایل‌های HTML و JS ماژول‌های Core گزارش شکاف می‌دهد؛ آمار آن heuristic است، ادعای «پوشش کامل» ندارد.
- ترجمه صفحات ورود، داشبورد، وب‌سایت‌ها، DNS، دیتابیس، SSL، Backup، WordPress، Docker، AI Scanner، خطاها، جدول‌ها، اعلان‌ها، فرم‌ها و AngularJS باید *به تفکیک ماژول* تست شود.
- اصلاح RTL همه جدول‌ها، نمودارها، inputها، آدرس IP، مسیرهای فایل، کدها و شمارنده‌های LTR در فارسی ضروری است. تغییر جهت خودکار global CSS به‌تنهایی کافی نیست.
- پایداری انتخاب زبان با `POST` دارای CSRF و cookie اختصاصی Django، محدود به `en/fa`، و `Secure/HttpOnly/SameSite` از شروط استقرار است.
- قبل از استقرار، تطبیق نسخه واقعی Core و تفاوت‌های تولیدی آن با upstream، تست مرورگر EN/FA در عرض‌های مختلف، و login/2FA باید انجام شود.

## نتیجه ممیزی مستقل کل Core (baseline upstream stable)

گردش‌کار [CyberPanel Master whole-Core i18n baseline audit](https://github.com/hooshedigital/CyberPanel-Master/actions/runs/44797500684) واقعاً سورس upstream stable را کلون کرده، اسکن را اجرا و فایل گزارش را به‌عنوان artifact ثبت کرده است.

- **۳۴ ماژول** در سورس مبنا
- **۲٬۲۴۱ فایل** HTML و JavaScript بررسی‌شده
- **۶٬۲۳۳ تگ ترجمه Django** شناسایی‌شده
- **۳۰٬۵۵۹ نمونه احتمالی متن‌های سخت‌کدشده** (heuristic، شامل تکرار و JS؛ این تعداد به‌معنی رشته ترجمه‌نشده قطعی نیست)

این baseline **نسخه نصب‌شده production نیست**. پس از source parity، همین ابزار را باید روی نسخه نصب‌شده اجرا کرد و بر اساس ماژول، واژه‌نامه ثابت، تفاوت‌های UI، gettext و JS اصلاح کرد. تا آن زمان نباید ادعا کرد ۱۴۲ ترجمه پوسته کل CyberPanel Master را فارسی کرده‌اند.

## مرکز ایجنت و عملیات

- ایجنت موجود `hoosh-cyberagent` نسخه سورس ۰.۹.۰ تنها منبع اصلی وضعیت است؛ مغز پارسا، Owner Broker و Gateway سرویس‌های مستقلی هستند.
- نما باید کارت‌های واقعیِ وضعیت سرویس‌ها، دیسک، RAM/Swap، هشدارها، check count، عملیات پیشنهادی و سطح مجوز را نشان دهد.
- `operations_center.py` از heartbeat واقعی با `updated_at_unix` استفاده می‌کند و فقط checkهای allowlist را با نام فارسی/انگلیسی منتشر می‌کند؛ متن logs، tokenها یا خروجی فرمان وارد مرورگر نمی‌شود.
- طراحی UI از کلاس‌ها و آیکون‌های خود Core بهره می‌گیرد و `/backup/master/` در این طراحی فقط مرکز عملیات است.
- **اجرای عملیاتی از صفحه وب هنوز فعال نیست**. برای صدور فرمان واقعی، queue امضاشده + RBAC + approval با TTL + worker غیرروت/محدود + audit + توقف/rollback لازم است. هیچ دکمه دروغین «انجام شد» مجاز نیست.

## AI Scanner معادل مستقل و قانونی

طبق راهنمای رسمی CyberPanel، AI Scanner آن شامل Quick/Full، کشف فایل‌ها، تحلیل، گزارش severity و پیشنهاد رفع اشکال است. دسترسی به مدل/سرویس پرداخت CyberPersons به معنی خرید اسکن و credentialهای ارائه‌دهنده است. کپی کردن API خصوصی، دورزدن لایسنس یا نمایش نتایج ساختگی مجاز نیست.

`master_extensions/wordpress_security_scan.py` **یک موتور مستقل و واقعی مرحله اول** است:
- تحلیل خواندنی کد PHP وردپرس و تشخیص تعدادی indicator، بدون اجرای PHP یا ارسال کد سایت به سرویس ثالث؛
- محدودیت زمان، حجم کل خواندن، اندازه هر فایل، عمق پوشه، تعداد فایل‌ها و نتیجه `partial`؛
- عدم دنبال‌کردن symlink/mount و عدم تولید محتوای فایل یا secret در گزارش؛
- ثبت شناسه Rule، سطح خطر، مسیر نسبی و هش شاهد برای بررسی اپراتور؛
- `files_modified=0`، و `ai_analysis_performed=False` به‌طور صریح؛ صرف تشخیص الگوی خطر معادل «AI/zero-day detection» نیست.

**تا عملیاتی شدن داخل سایت:**
1. نگاشت شناسه WordPress سایت به رکورد `Websites` با ACL واقعی و محدودیت مالکیت دامنه؛ هرگز مسیر آزاد از مرورگر دریافت نشود.
2. صف‌بندی کار در worker با UID همان وب‌سایت، محدودیت I/O/CPU و نرخ، تهیه report و تاریخچه بدون افشای سورس.
3. نمایش progress و گزارش reviewable در پنل با دو حالت Quick/Full، و workflow تحلیل اختیاری AI فقط با Gateway مجاز و تأیید هزینه/حریم خصوصی.
4. CVEهای شناخته‌شده WordPress، پلاگین‌ها، تم‌ها و تطبیق نسخه‌ها با feed معتبرِ به‌روز، بدون ادعای یافتن همه بدافزارها.
5. remediation فقط پیش‌نمایش؛ quarantine/delete با بکاپ، RBAC و مرحله تأیید جدا.
6. تست روی وردپرس آزمایشی، false-positive و benchmark؛ نباید به‌صورت خودکار فایل مشتری حذف یا تغییر داده شود.

**نکته امنیتی:** نسخه‌های قدیمی کد upstream AI Scanner سابقه نقص امنیتی callback داشته‌اند؛ برای نسخه نصب‌شده باید مسیرها، auth و وضعیت patch واقعی بررسی شوند. با فعال‌سازی سریع endpoint عمومیِ ناایمن، امنیت سرور به خطر می‌افتد.

## سایر قابلیت‌های Premium

برنامه عملیاتی مستقل برای SSL Manager، WordPress Pro، Backup v2، Email Debugger، Root File Manager، Rspamd، Roundcube و امکانات پیشرفته امنیت/میزبانی باید **feature-by-feature** تهیه شود. هیچ دکمه یا بخش بدون back-end واقعی «فعال» نمایش داده نشود. امکانات رایگان موجود مثل Docker Manager و File Manager معمولی تکرار نشوند.

## ترتیب پذیرش

۱. ممیزی فایل‌ها و locale و CSS/JS **کل Core نصب‌شده** و نسخه سنجی؛ تهیه آرشیو قابل بازگشت قبل از تغییر.  
۲. تست ترجمه سراسری en/fa در staging، به‌ویژه login/CSRF/2FA و فرم‌ها.  
۳. بازطراحی یکپارچه shell/sidebar/header/agent console با منطق Core موجود و آزمون موبایل و دسکتاپ.  
۴. اتصال scanner و عملیات Agent به worker با RBAC/approval/queue؛ تأیید مستقل و تست end-to-end.  
۵. استقرار کاناری و مرور با حساب واقعی مالک؛ فعال‌سازی نهایی پس از QC، health checks و rollback.  

**آماده‌بودن سورس و CI سبز به معنی تکمیل کل محصول یا استقرار زنده نیست.**
